# Backend operations required per feature

The frontend simulates these operations in mock mode (always labelled). The local FastAPI
backend must perform them for production. Contract details: `docs/api-adapter.md`.

| Feature                 | Real backend operation                                                                                                                                                                                                                                | Frontend behaviour                                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Executive dashboard     | Aggregate Yeastar P550 CDR/queue statistics per day, queue (6001 Sales, 6002 After-Sales) and agent: incoming, answered, missed, abandoned, wait and talk time.                                                                                       | Computes SLA = (Incoming − Missed) ÷ Incoming × 100, keeps missed and abandoned separate, never estimates PBX figures from recordings. |
| Quality figures         | Serve all evaluations (immutable history) with call date and filters.                                                                                                                                                                                 | Pools per call using the latest completed evaluation; excludes "Insufficient evidence — No score".                                     |
| Live center             | Stream or poll Yeastar queue/agent events (waiting calls, agent states, active calls) with masked caller numbers.                                                                                                                                     | Polls `/live/status` every 5 s.                                                                                                        |
| Calls                   | Ingest recordings from the PBX, transcribe (on-premise AI), attribute speakers (dual channel) or mark unresolved (mixed), classify, score; serve masked caller numbers; paginate and filter server-side.                                              | Filters/pagination in the URL; never shows unmasked numbers.                                                                           |
| Call review             | Persist review status/note with reviewer and time; audit trail.                                                                                                                                                                                       | Requires a note for "Needs follow-up".                                                                                                 |
| Customer insights       | Classify calls (reason, complaint, service request, confidence) with the on-premise model.                                                                                                                                                            | Aggregates reasons and complaint trends; drill-through to calls.                                                                       |
| Reports                 | Produce queue and agent report data; draw a random audio sample (5 answered recordings ≥ 60 s per agent) with an auditable seed; store report history; send the combined management email via the Microsoft 365 sender (Phase B).                     | Previews reports, exports .xlsx client-side, shows sample shortages, email is simulated in mock mode.                                  |
| Uploads                 | Store uploaded audio, run the processing pipeline, report stage progress.                                                                                                                                                                             | Validates type/size and a synthetic-data confirmation; polls status.                                                                   |
| Queue administration    | Persist queues (never delete), enforce unique numbers, require `confirm` for renumbering/disabling/removing agents, update agent assignments, audit every change.                                                                                     | Validates, asks for confirmation, shows history.                                                                                       |
| AI administration       | Report installed models and service status; store immutable configuration versions; apply limits, prompts, scorecard binding and dictionary in the processing pipeline; run the job queue (pause/resume/retry/cancel).                                | Simulates status, model switching and queue progress.                                                                                  |
| Iraqi Arabic dictionary | Store entries with immutable versions; apply active entries during transcription/normalization; enforce the four-eyes review of corrections.                                                                                                          | Normalized search and duplicate checks mirror the server.                                                                              |
| PBX administration      | Own the vendor adapters (Yeastar P550 first); store settings and the write-only secret; test the connection; poll CDR, recordings and queue statistics from the ingestion start date; run manual synchronizations.                                    | Never connects; tests check settings only; syncs count existing synthetic records.                                                     |
| Notifications and email | Send through the dedicated Microsoft 365 sender (app registration, write-only secret); evaluate notification rules; render versioned templates; record every delivery.                                                                                | Records simulated deliveries; sends nothing.                                                                                           |
| Report configuration    | Store versioned sampling/default/delivery settings; generate reports on request with an auditable random sample; reject automatic scheduling until authorized.                                                                                        | Generates from synthetic data; email simulated.                                                                                        |
| Audit log               | Append-only `GET /admin/audit?resource=&resource_id=` for every administration action (who, what, when, before/after; never secrets).                                                                                                                 | Shown on every admin page.                                                                                                             |
| Users and roles         | Store accounts with unique, verified emails; enforce roles/permissions on every route; last-admin and self-change protections; email verification links; never create agent accounts.                                                                 | Validates, confirms sensitive changes, shows effective access.                                                                         |
| Authentication and MFA  | Password hashing, mandatory TOTP (RFC 6238, Microsoft Authenticator compatible) with encrypted secrets, recovery codes shown once and stored hashed, lockout and session policy, revocation, reset links, MFA reset requiring a second administrator. | Shows the workflows; never produces secrets, QR codes or recovery codes; checks only formats.                                          |
| Storage and retention   | Report real volumes and usage; move data between locations in monitored jobs; apply retention by moving items to recovery; serve no recovered item until restored; permanent deletion only under an approved policy.                                  | Estimates usage from synthetic data; hides recovered items in the mock.                                                                |
| Backup and restore      | Encrypted backups of database, recordings, transcripts, QA/KPI results, scorecard versions, users, settings, audit history and required secrets; checksum verification; isolated test restores; full restore with maintenance mode; migration export. | Every run is "simulated"; readiness stays blocked until the service exists.                                                            |
| System health           | Collect service health, CPU/RAM/GPU/disk metrics, worker heartbeats and structured, sanitized error records with correlation IDs.                                                                                                                     | Polls simulated metrics; redacts messages again on display.                                                                            |
| Audit log               | Store append-only, tamper-evident entries with result and correlation ID; filter server-side; audit exports; never record passwords, secrets, one-time codes or recording content.                                                                    | Read-only view and Excel export.                                                                                                       |
| General and branding    | Store versioned application settings and branding; serve approved local assets under `/brand/`; apply default language/theme for users without preferences.                                                                                           | Validates paths and colour contrast; applies branding at runtime.                                                                      |

## Enforcement that only the backend can provide

The frontend hides or disables actions by permission and asks for confirmation, but these are
conveniences. For production the backend must:

1. Authorize every request by permission (see the matrix in `docs/handoff.md` §6) and reject
   missing `confirm: true` on destructive or scope-changing requests with 409.
2. Enforce self-protection (own role/status, own MFA reset), the last-active-administrator rule
   and four-eyes reviews (dictionary corrections, MFA reset by another administrator).
3. Implement production sign-in (password + mandatory TOTP), lockout, session idle/maximum
   limits, CSRF validation and revocation.
4. Keep all secrets write-only and out of responses, logs and audit entries; sanitize error text.
5. Report PBX, AI, email, backup and restore outcomes only for operations actually performed —
   the frontend labels everything from the simulated backend as simulated and never claims
   success for them.
6. Never delete permanently without an approved retention policy; the frontend offers no
   permanent-deletion action.
