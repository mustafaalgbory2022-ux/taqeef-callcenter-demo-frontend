### Hide / restore ambiguities (not invented; mock-only assumptions)

- **Repeating an action with a new `request_id`** (hiding a hidden call, restoring a visible one): v0.3 does not define the result. The UI only offers the valid action; the mock answers 409 without a field reason.
- **`GET /api/calls/{call_id}` on a hidden call:** not stated. The frontend and mock assume it returns the call with `hidden: true`, which restore needs.
- **Payload hash:** the real server hashes the non-sensitive fields (`reason` excluded, §2.1); the mock keys replay on the route only.
- **Hidden calls in the list UI:** the client supports `include_hidden=true`; no list toggle is offered yet.
- **`latest_job`:** decoded; the simulated pipeline has no jobs, so the mock always sends null and the UI does not show it yet.
